PARTE 1 - Atletico Caffeina (ft-mvp-7), 25 player

1. Query rosa attuale (sorgente di verita' = DB, mai liste stantie):
   SELECT c.player_id, p.full_name, p.role_classic
   FROM contracts c
   JOIN players p ON p.id = c.player_id
   WHERE c.fanta_team_id = 'ft-mvp-7'
   ORDER BY p.role_classic, p.full_name;

2. Diff con avatar esistenti - per ciascuno dei 25:
   - Se /avatars/<id>.webp esiste E players.photo_cartoon_url popolato
     -> SKIP (probabilmente gia' processato come "extra" del T120 vecchio)
   - Se file esiste ma photo_cartoon_url NULL -> SOLO UPDATE DB, no
     rigenerazione
   - Se file non esiste -> pipeline completa

3. Pipeline completa per i mancanti (identica a T120b):
   PicWish cutout -> normalize bbox iniziale -> matte bianco ->
   face-to-many Combo B (instant_id 0.55, denoising 0.78, prompt+negative
   come T120) -> BiRefNet -> normalize iconografico 95% bbox (step finale
   gia' in batch-avatars.ts) -> save mister-web/public/avatars/<id>.webp
   -> UPDATE players SET photo_cartoon_url

PARTE 2 - 8 allenatori

   SELECT DISTINCT c.id, c.lastname, c.photo_url, c.photo_cartoon_url

   Atteso: 8 coach (Allegri, Baroni, Gasperini, Conte, Tudor, Sarri,
   Juric, Chivu).

2. Stessa pipeline dei player, applicata a coaches.photo_url come input.

3. PATH SEPARATO per evitare collisioni di ID con i player:

   (crea la cartella se non esiste).

4. UPDATE coaches SET photo_cartoon_url = '/avatars/coaches/' || id ||
   '.webp' per ciascun coach.

5. Verifica che il frontend (MatchMiniCoachToken) usi gia' il pattern
   photo_cartoon_url ?? photo_url - se si', tutto si aggiorna in
   automatico. Se serve modificare l'URL pattern atteso, segnalalo.

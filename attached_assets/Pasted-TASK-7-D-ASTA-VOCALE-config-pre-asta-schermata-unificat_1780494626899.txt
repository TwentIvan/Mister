==== PARTE 3 — Integrazione voce ====
Web Speech API del browser (window.SpeechRecognition || webkitSpeechRecognition), lang 'it-IT', continuous=true, interimResults=true. NIENTE backend STT.
Attivazione: pulsante toggle Microfono. On = ascolto continuo (il primo on fa comparire il prompt permessi del browser). Off = stop. Su recognition.onend, se il toggle e ancora ON, RIAVVIA il recognition (altrimenti Chrome lo ferma dopo il silenzio).
Parsing (agisci SOLO sui risultati FINAL / isFinal; debounce comandi identici entro ~1.5s per non eseguirli due volte). Normalizza il transcript (minuscolo, niente accenti), poi in ordine:
1) Controlli (wake-word "mister"):
   - "mister salta"    -> handleSalta()
   - "mister pausa"    -> pausa
   - "mister riprendi" -> riprendi
2) Aggiudica: "giocatore aggiudicato" -> handleAggiudica()
3) Offerta: pattern "[nome] [numero]" -> offerta ASSOLUTA.
   - Match del nome: FUZZY sui nome_asta dei team (normalizzati). Soglia ragionevole; gestisci nomi multi-parola.
   - Numero: parsa sia cifre ("15") sia parole italiane ("quindici"). Mappa 0-99 + parsing cifre.
   - Chiama lo STESSO placeBid(fantaTeamId, amountFmAssoluto) usato dai tasti. I tasti passano currentBid + N; la voce passa il numero assoluto. Cosi timer (setDeadlineTs) e guard (isTransitioningRef + match player_id) valgono identici per la voce. NESSUN path parallelo.
   - Se il backend rifiuta (es. importo <= offerta corrente), l'errore inline gia presente si mostra.
Feedback UI (visibile, serve in demo):
   - Trascrizione live di cio che il mic sente.
   - Conferma del comando riconosciuto (es. "Offerta: Trastevere 15", "Comando: salta") con un flash breve.
   - Comando non riconosciuto: ignorato, nessun effetto.
I tasti restano come fallback.
